Узкие места

Конкретные точки, где теряются деньги, время или данные. Каждая — с числом и источником.

1
Нулевая выручка при готовом продукте
НЕИЗВЕСТНО Нет pricing, нет лендинга, нет публичного доступа. 2 289 строк кода работают, но не продаются. Каждый день без pricing = потерянная возможность. [PRD.md, GitHub: private]
2
Нет обратной связи от клиентов
НЕИЗВЕСТНО Единственный упомянутый клиент — Sisi. Нет NPS, нет логов использования, нет канала feedback. Продукт развивается в вакууме. [PRD.md]
3
Wizard требует Python + git для запуска
ФАКТ Целевая аудитория = "beginners", но установка требует git clone + python3. 0 из 52 файлов содержат GUI или web-интерфейс. [install.command, README.md]
4
10 коннекторов в конфиге, 0 проверены с клиентом
ГИПОТЕЗА connectors.json описывает 10 интеграций, но ни одна не тестировалась с реальным клиентом. 6 из 10 имеют статус "planned" или "manual-export-first". [connectors.json]
5
Всё в одном файле: setup_vault.py = 640 строк контента
ФАКТ setup_vault.py содержит 640 строк — весь контент vault (промпты, правила, чеклисты) захардкожен как строки Python. Изменение любого текста = изменение кода. [scripts/setup_vault.py]
6
Нет Windows-поддержки
ФАКТ install.command = zsh-скрипт, только macOS. BACKLOG.md упоминает "Add Windows install script if needed" — не реализовано. [install.command, docs/BACKLOG.md]

07

Контуры внедрения и отсутствующие артефакты

Что можно улучшить — автоматизация процессов и недостающие операционные документы.

7a. Контуры автоматизации

Лендинг + pricing page

Критичный
Зачем: Без лендинга продукт невидим. Клиент не может узнать о POS FOR BEGINNERS без личного контакта с Максимом.
АВТОМАТИЗИРОВАТЬ
Генерация лендинга из README + ROADMAP. Деплой на Vercel/Netlify. Stripe/Lemon Squeezy для оплаты.
ОСТАВИТЬ ЧЕЛОВЕКУ
Позиционирование, pricing тиры, копирайтинг, value proposition.
Риск: лендинг без чёткого value proposition = трафик без конверсии.

Телеметрия wizard (анонимная)

Высокий
Зачем: Сейчас 0 данных о том, сколько людей запускают wizard, на каком шаге останавливаются, какие коннекторы выбирают.
АВТОМАТИЗИРОВАТЬ
Opt-in телеметрия в setup_pos.py: какие шаги выполнены, сколько коннекторов, какие ошибки. Отправка в простой webhook (n8n / Supabase).
ОСТАВИТЬ ЧЕЛОВЕКУ
Анализ данных, решения по приоритизации фич.
Риск: Privacy-sensitive — нужен явный opt-in и no-PII policy.

Выделение контента из кода

Высокий
Зачем: 640 строк контента (промпты, правила, чеклисты) захардкожены в setup_vault.py. Изменение текста = изменение Python-кода.
АВТОМАТИЗИРОВАТЬ
Вынести весь контент в templates/*.md. setup_vault.py читает файлы вместо строковых констант. Jinja2 или простой string.format.
ОСТАВИТЬ ЧЕЛОВЕКУ
Редактирование и улучшение текстов.
Риск: Минимальный — рефакторинг, не изменение поведения.

Web-версия wizard

Средний
Зачем: Целевая аудитория — начинающие. Git clone + python3 — это барьер. Web-wizard снижает порог входа до нуля.
АВТОМАТИЗИРОВАТЬ
Next.js / static page с формами. Генерация zip-файла с готовым vault. Download вместо git clone.
ОСТАВИТЬ ЧЕЛОВЕКУ
UX-дизайн, тестирование с начинающими.
Риск: Scope creep — из CLI-инструмента в web-app. Только после validation с 5+ клиентами.

7b. Отсутствующие артефакты

1.1 North Star Metric (NSM) — ОТСУТСТВУЕТ
Симптом: Непонятно что считать успехом — количество клиентов? wizard completions? retention?
Риск: Развитие фич без привязки к ценности для клиента
Минимум: Одно предложение: «NSM = количество клиентов, дошедших до Step 08 (POS MVP)»
Приоритет: Критичный
1.3 Quarterly OKR — ОТСУТСТВУЕТ
Симптом: Бэклог есть (BACKLOG.md), но нет фильтра «что изменится через 90 дней»
Риск: Бэклог растёт без приоритизации
Минимум: 1 Objective + 3 Key Results на Q3 2026
Приоритет: Высокий
3.1 Единый источник правды (SSOT) — ЧАСТИЧНО
Симптом: vault_structure.json — хороший SSOT для структуры. Но нет SSOT для метрик, клиентов, выручки
Риск: При масштабировании — данные будут в разных местах
Минимум: Таблица: метрика / файл-владелец / дата обновления
Приоритет: Высокий
3.2 Определения метрик — ОТСУТСТВУЕТ
Симптом: Нет определения «клиент» (тот кто запустил wizard? дошёл до step 8? заплатил?)
Риск: Невозможно считать конверсию без определения этапов
Минимум: 5 определений: lead, trial, active client, churned, MRR
Приоритет: Критичный
2.4 Список запрещённых действий — ЕСТЬ ДЛЯ КЛИЕНТА, НЕТ ДЛЯ ПРОДУКТА
Симптом: SECURITY.md и AGENTS.md содержат ограничения для клиентского агента, но нет аналога для разработки самого продукта
Риск: Агент-разработчик может сломать клиентский vault при обновлении
Минимум: Секция в AGENTS.md: «Никогда не менять формат pos-progress.json без миграции»
Приоритет: Высокий
4.1 Журнал решений — ОТСУТСТВУЕТ
Симптом: Решения (10 коннекторов, 8 шагов, Python-only) приняты, но причины не записаны
Риск: Те же вопросы обсуждаются заново при привлечении партнёра/разработчика
Минимум: Файл с 5-10 записями: дата / решение / причина
Приоритет: Средний

08

Приоритеты

Что делать первым, что потом, что позже. Три горизонта + план на 1 час если нужно начать прямо сейчас.

СЕЙЧАС — 1-2 недели

1. Определить pricing. Минимум: одна цена за "POS setup" (консалтинг). Записать в канонический файл.

2. Провести 3 клиента через wizard. Собрать feedback: где застревают, что непонятно, что лишнее.

3. Написать NSM + определения метрик. 30 минут работы, критически важно для всех дальнейших решений.

ПОТОМ — 1-2 месяца

4. Лендинг + payment. Простая страница: что это, для кого, цена, CTA. Stripe/Lemon Squeezy.

5. Вынести контент из setup_vault.py. Templates/*.md вместо Python-строк. Упрощает редактирование.

6. Opt-in телеметрия. Какие шаги проходят, где бросают, какие коннекторы выбирают.

ПОЗЖЕ — квартал+

7. Web-wizard. Только если validation покажет спрос > 10 клиентов/месяц.

8. Шаблоны для ниш. POS for freelancers, POS for students, POS for startups — разные vault_structure.json.

9. Marketplace скилов. Клиенты делятся кастомными скилами. Только после 50+ активных пользователей.

  1. Определить цену (10 мин) — записать в файл: «POS setup = X EUR, включает: …»
  2. Написать NSM (5 мин) — «NSM = clients reaching Step 08»
  3. Сделать repo public (2 мин) — или создать отдельный public fork
  4. Написать 1-paragraph pitch (10 мин) — для отправки потенциальным клиентам
  5. Отправить pitch 3 людям (15 мин) — Telegram/email, конкретные люди
  6. Создать feedback-форму (10 мин) — Tally/Typeform, 5 вопросов после wizard
